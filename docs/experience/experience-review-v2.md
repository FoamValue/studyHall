## 1. 体验目标与方法

以 3–6 岁孩子「在平板上打开就能看、能一直看下去」的真实使用路径为准，用 Playwright 在 iPad 横屏尺寸下实机走查，逐步截图并度量关键尺寸。

- **体验路径**：打开首页（默认植物板块）→ 依次切换 动物 / 昆虫 / 恐龙 板块 → 回植物板块切二级分类（全部 / 花朵 / 树叶 / 果实）→ 进植物详情（花 / 叶 / 果 切换）→ 进动物详情（单图）→ 点中 / 英喇叭 → 进恐龙详情 → 点「回花园」校验板块、分类与滚动位置记忆。
- **度量维度**：可见信息量、图片尺寸与竖向留白、字号与热区、板块切换与排序稳定性、单图详情是否无部位切换、小知识渲染、音频请求契约、异常边界（溢出、快速连点、回退）、控制台报错。
- **度量方式**：脚本读取元素尺寸、`document.scrollHeight` 与计算样式，逐屏截图留证；音频以网络请求与 `HTMLAudioElement` 状态判据。

## 3. 正向结论（保持住的体验）

1. **四板块两级导航成立**：一级板块切换清晰，二级分类**仅**出现在植物板块；动物 / 昆虫 / 恐龙平铺，10 种基本一屏可见，符合「板块即浏览粒度」的设定。
2. **单图模型正确**：动物 / 昆虫 / 恐龙详情**零部位切换按钮**；植物详情 3 部位切换与 US-8 语义不回归。
3. **排序真正生效**：`sort` ASC + `id` ASC 在「切走再切回」与「整页 reload」两种路径下顺序完全一致，Sprint 4 遗留的「依赖 Mongo 自然序」已彻底消除。
4. **音频机制落地**：请求 URL 与 PRD 契约一致（`/audio/{id}-zh.m4a`、`-en.m4a`），真实资源 206 可取、`readyState=4` 可解码；缺失时喇叭不渲染且**不**回退浏览器合成，降级干净无报错。
5. **Sprint 6 无滚动修复保持**：详情页页面级 X / Y 溢出均为 0，内容区不滚动，1024 与 1180 双尺寸一致。
6. **热区与运行健康**：全站 **0** 个小于 56px 的可点元素；控制台 0 报错；状态记忆（板块 + 分类 + 滚动）精确。
7. **v1 的小微优化未回归**：卡片次级文字 16px（v1 F4 已修）、横屏主图 48% 上限（v1 F2/EX-2 已修）均保持。

## 4. 发现与建议（交 PO）

### F1 [P1 · 问题] 「小知识」改称只落在无障碍名上，页面上看不到
- **现象**：`.allusion-card` 仅通过 `aria-label="小知识"` 承载语义，**页面上没有任何可见的「小知识」标题文字**（详情页可见文本不含「小知识」）。对视力正常的 3–6 岁孩子与陪同家长而言，这张卡片是「没有名字的一块色块」。
- **证据**：`pf2-05-detail-animal-giant-panda-1024x768`、`pf2-06-detail-dinosaur-tyrannosaurus-1024x768`；DOM 复核 `visible text contains 小知识 = false`。
- **根因（初判）**：`AllusionCard` 未渲染可见标题，改名只在 `aria-label` 上生效（S9-4 的称谓变更**未真正对用户可见**）。
- **建议**：在卡片内渲染可见小标题「小知识」（可配轻量图标），字号 ≥20px、与卡片正文层级协调；纯前端改动，不动语料与接口。
- **影响**：低风险小微改动；属「需求文本已改、用户界面未改」的落地缺口。

### F2 [P2 · 小微优化] 单图详情主图偏小，竖向留白约 265px
- **现象**：动物 / 昆虫 / 恐龙详情无部位切换按钮，横屏图片栏只占 48% 宽；实测主图 419×419 而 `.detail-body` 872×684 —— 图片仅占可用高度 **61%**，下方约 **265px** 空着，画面重心偏小。
- **证据**：`pf2-05-detail-animal-giant-panda-1024x768`、`pf2-09-detail-animal-giant-panda-1180x820`、`pf2-06-detail-dinosaur-tyrannosaurus-1024x768`。
- **根因（初判）**：横屏 `.detail-body` 图片栏固定 `grid-template-columns: 48% ...`，正方形图被栏宽限制，竖向富余空间未被利用（植物板块右侧需容纳部位按钮，故 48% 合理；**单图板块并无此约束**）。
- **建议**：对**单图板块**放宽横屏图片栏比例（如 48% → 约 60%）并提高图片 `max-height` 至可用高度的 ~85%，让主图吃掉竖向空间；**植物（三部位）版式维持现状**；改后须实测 1024×768 与 1180×820 的长文案条目不溢出。
- **影响**：仅横屏样式分支，不涉结构、不涉接口；建议与「单图模式」判定条件绑定，避免误伤植物详情。

### F3 [P2 · 较大 → 建议排后续 Sprint] 首页植物「全部」无分页 / 增量加载、无总量提示
- **现象**：植物板块「全部」100 张卡、`scrollHeight` 达 **8764px**（1180×820 为 **9739px**），首屏仅见 **8 张**；既无「翻页 / 滚动增量加载」，也无「共 N 种」提示，孩子与家长不易预期还有多少内容。
- **证据**：`pf2-01-home-plant-all-1024x768`、`pf2-07-home-plant-all-1180x820`。
- **对照**：PRD §4.1 要求「植物总数超过一屏需支持翻页或滚动加载」；本项为 v1 报告 F3 / F5 的**复现**（当时裁决「排后续 Sprint」，至今未落地）。
- **建议**：纳入 Sprint 10 做首屏 + 分段滚动加载，并在筛选条旁显示「共 N 种」；动物 / 昆虫 / 恐龙板块（10 种、`scrollHeight` 1328）**无需**处理。
- **影响**：前端加载策略改动为主，属结构性改动，非小微；回归面需覆盖分类筛选、滚动记忆与 E2E 列表断言。

### F4 [P2 · 产品建议] 恐龙「纯骨架化石」对低龄辨识度有限
- **现象**：恐龙板块一律完整骨架化石图（§14 既定），3–6 岁孩子难以把「骨架」与「霸王龙」的形象联系起来；当前小知识为纯文字，没有图示或对照提示辅助建立关联。
- **证据**：`pf2-06-detail-dinosaur-tyrannosaurus-1024x768`。
- **建议（供 PO 评估，非本 Sprint 必做）**：后续为恐龙补充「骨架 + 复原图」对照，或在详情增加一句低龄化引导（如「它活着的时候长这样」）；若采纳，需先解冻 §14.6「不做恐龙写实复原图」的约束。
- **影响**：涉及内容口径与资产生产，建议单列内容策略议题，不塞进小微优化 Sprint。

### F5 [信息 · 待人工抽验] 音频真机听感无法自动化判定
- **现象**：走查环境（headless）实测可加载解码（`readyState=4`、`duration` 0.747s / 0.853s、响应 206），**但音量 / 音色 / 是否实际出声**无法在静音环境判定。
- **建议**：由人工在 iPad 上抽验中文 / 英文朗读的可听性与音量（沿用既有「真机由人工抽验」口径）。
- **补充说明**：本次走查未发现「缺英文音频」的真实样本（130 条 zh + en 齐全），缺失降级路径已由**合成条件**验证通过。

### F6 [信息 · 已核实非缺陷] 「回花园后滚动值与点击前不同」
- **现象**：动物板块点首卡前后 `scrollY` 记录值（320 → 254）不一致，初看像状态记忆偏差。
- **核实结论**：Playwright 点击时自动将目标卡片滚入视口，应用保存的是**点击瞬间**的真实 `scrollY`（254），返回后 `scrollY` = 254，与存储值**完全一致** → 记忆精确，**非缺陷**。

**PF 总体意见**：v2.0 的能力落地质量高——四板块结构、单图模型、排序与音频机制都经得起实测，**没有发现功能性缺陷**。最值得优先处理的是 **F1（「小知识」称谓对用户不可见，属需求未真正落地的缺口）** 与 **F2（单图详情白白空着 265px 竖向空间，改动小、收益直接）**；**F3（首页加载策略）** 已在 v1 被推迟过一次，建议本次正式排期，避免第三次顺延。
