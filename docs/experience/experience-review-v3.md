## 1. 体验目标与方法

三位体验官分工，从三个不同角度对已交付的 v2.2 线上形态做深度走查：

- **PF-A｜幼儿独立操作可用性**：假设孩子独自操作（不识字、手指粗、爱乱点），检查三步到达、热区、返回与状态记忆、误操作容忍度。
- **PF-B｜横屏视觉与版式**：以 iPad 横屏为基准，度量版式比例、字号层级、图片占比与留白、四视口一致性。
- **PF-C｜边界异常与性能**：压测增量加载、快速连点、异常 id、刷新、键盘、音频与网络错误，采集控制台与网络证据。

**体验路径**：首页（默认植物）→ 切 动物 / 昆虫 / 恐龙 板块 → 回植物切二级分类（全部 / 花朵 / 树叶 / 果实）→ 植物详情（花 / 叶 切换）→ 动物详情（单图）→ 恐龙详情 → 点中 / 英喇叭 → 回花园校验板块 / 分类 / 滚动 → 边界压测。

**度量方式**：Playwright 读取元素 `getBoundingClientRect`、`getComputedStyle`、`document.scrollHeight/scrollWidth`、网络响应状态与 `console` 事件，逐屏截图留证。

| 触控热区（首页） | 板块/分类按钮 92×56 / 128×56；卡片 226×310；**<56px 热区 0 项** | 达标 |

## 5. 发现与建议（交 PO / UI）

### N1 [P1 · 问题] 返回按钮四板块统一「← 回花园」，与站点四板块定位不符
- **现象**：植物 / 动物 / 昆虫 / 恐龙四个板块的详情页返回按钮**文案完全相同**，都是「← 回花园」（16 次采样全一致）。站点已升级为「自然小图鉴」四板块，动物 / 昆虫 / 恐龙并非长在花园里，孩子看到「回花园」会迷惑。
- **证据**：`pf3-a-02`、`pf3-b-05-detail-animal-1024x768.png`、`pf3-b-06-detail-dinosaur-1024x768.png`；[PlantDetailPage.jsx](file:///Users/chenxinjie/Mirror/github/studyHall/frontend/src/pages/PlantDetailPage.jsx#L237-L243) 硬编码文本「← 回花园」，异常兜底处亦为「回花园看看」（[L205](file:///Users/chenxinjie/Mirror/github/studyHall/frontend/src/pages/PlantDetailPage.jsx#L205)）。
- **建议**：返回文案按当前板块派生（如 植物→「回花园」、动物→「回动物世界」、昆虫→「回昆虫角」、恐龙→「回恐龙园」），或统一为中性「← 返回」。纯前端文案改动，不动接口与结构。
- **影响**：低成本、高一致性收益；属「站点定位已升级、文案未同步」的落地缺口。

### N2 [P1 · 内容缺口] 植物板块「小知识」严重缺失（176 / 206 部位为空）
- **现象**：植物 100 条目共 **206 个部位**，其中 **176 个部位没有任何小知识内容**（仅 30 个有），因此这些部位详情页「小知识」卡片**不渲染**（组件约定无内容不渲染）。相比之下，动物 / 昆虫 / 恐龙**各 30 条、0 缺失**，卡片都能正常出现。
- **证据**：语料校验（`plants parts=206 missingAllusion=176`；`animals/insects/dinosaurs missingAllusion=0`）；抽查 `anemone:flower`、`anemone:leaf`、`apple:flower`、`apple:leaf` 均为空。截图 `pf2/pf3` 植物详情对比单图详情。
- **根因**：植物语料的小知识覆盖率不足（v2.0 定义「小知识」时，动物 / 昆虫 / 恐龙逐条补齐，植物仅部分补），属**内容生产问题、非代码缺陷**。
- **建议**：走 AI 内容产线，为植物缺失部位补齐小知识（古诗典故 + 白话解释，沿用既有口径与长度红线）；通过 `scripts/import-plants.mjs` 导入，**无需改代码**。
- **影响**：内容侧工作量大（176 处），但不阻塞、不涉代码；建议单列内容扩容 Sprint。

### N3 [P2 · 小微优化] 详情页拼音字号（16px）小于英文（20px），发音辅助层级倒挂
- **现象**：横屏详情页中文名 40px、**拼音 16px**、英文 20px。拼音是低龄孩子「跟着念」的第一辅助，却比英文还小。
- **证据**：[styles.css](file:///Users/chenxinjie/Mirror/github/studyHall/frontend/src/styles.css#L464-L476) 横屏分支把 `.detail-pinyin` 压到 16px，而 `.detail-en` 保持 20px；实测字号见 §3.2。
- **建议**：横屏详情把拼音提到 **20px**（与英文对齐或略高），保持 `.detail-pinyin` 与 `.detail-en` 视觉层级一致；纯样式改动，注意不撑破竖向空间（双尺寸实测不溢出）。
- **影响**：低风险小微改动，孩子对发音辅助更易读。

### N4 [P2 · 小微优化] 板块 / 分类按钮字号 20px（幼儿场景可更醒目）
- **现象**：首页板块与二级分类按钮文字 20px / 600（按钮 92×56 / 128×56）。对 3–6 岁孩子，「动物 / 昆虫 / 恐龙」这类关键导航文字可以更大更醒目。
- **证据**：§3.1 字号实测；`pf3-a-01-home-plant-1024x768.png`。
- **建议**：板块/分类按钮文字 20px → 22~24px（按钮尺寸已达标，仅调字号），提升可读性与点击信心。
- **影响**：极低风险小微改动，需确认长文案（如「恐龙」）不换行溢出。

### N5 [P2 · 观察项] 竖屏单图详情竖向留白偏大（319px）
- **现象**：竖屏 768×1024 下，单图（动物 / 昆虫 / 恐龙）详情图片 451×451 居中，`.detail-body` 940px 高，下方留白 **319px**。
- **证据**：`pf3-c-06-detail-768x1024.png`（§3.4）。
- **说明**：竖屏**非主方向**（PRD 以横屏为基准），本项优先级低，仅记录；若后续要兼顾竖屏，可提高竖屏单图 `max-height`。
- **建议**：暂不处理，列入观察。

### N6 [信息 · 待人工抽验] 音频真机听感
- **现象**：走查环境 4/4 音频请求 200、可加载；但 headless 静音，**音色 / 音量 / 是否实际出声**无法判定。
- **建议**：沿用既有口径，由人工在 iPad 上抽验中英文朗读可听性。

## 6. 正向结论（保持住的体验）

1. **四视口零溢出**：1024×768 / 1180×820 / 1366×1024 / 768×1024 首页与详情页均无水平溢出；详情页 `scrollH==clientH`，Sprint 6 沉浸式不滚动机制保持。
2. **热区全达标**：首页、植物详情、动物详情 **0 个 <56px 热区**。
3. **增量加载落地**（EX-6 保持）：首屏 16 + 滚动步进，7 次到底渲染 100 卡，各板块 / 分类「共 N 种」计数正确。
4. **状态记忆精确**：板块 + 分类 + 滚动位置恢复偏差 = 0。
5. **健壮性无短板**：快速连点 12 次不崩、异常 id 兜底、刷新正常、键盘 ←→ 正常、控制台 0 报错、网络 0 失败。
6. **图片精度安全**（方案 B 验证）：最紧场景 1366×1024 单图 2x 所需 1554px ≤ 1600px，余量 46px，1600 下限判断正确。
7. **v2 三项优化均保持**：小知识可见标题（EX-4）、单图横屏放大（EX-5）、增量加载 + 总量提示（EX-6）全部生效，无回归。
