## 1. 体验目标与方法

以 3–6 岁孩子「在平板上打开就能看、能一直看下去」的真实使用路径为准，用 Playwright 在 iPad 横屏尺寸下实机走查，逐步截图并度量关键尺寸。

- **体验路径**：打开首页 → 切换分类（全部 / 花朵 / 树叶 / 果实）→ 点卡片进详情 → 沉浸式看花/叶/果 → 点「下一株」连续换株 → 点喇叭听中英文名 → 进入系统全屏 → 退出全屏 → 回花园（校验分类与滚动位置记忆）。
- **度量维度**：可见信息量、图片大小与留白、字号与热区、切换响应、异常边界（长文案、快速连点、滚动、退出全屏）、控制台报错。
- **度量方式**：脚本读取元素尺寸与文档 `scrollHeight`，并逐屏截图留证。

## 3. 正向结论（保持住的体验）

1. **Sprint 6 修复到位**：详情页整屏无滚动条，滚动不再带动页面、不再退出全屏；图片与文字均完整。
2. **热区全部 ≥56px**：两侧换株按钮、回花园、喇叭、部位按钮都足够大，手指点按友好。
3. **切换流畅**：换株 <1s 且无闪烁；切株后无朗读残音；快速连点最终图完整（`naturalWidth=1920`）。
4. **沉浸感达成**：进入详情即全屏式看图，配合「上一株 / 下一株」可连续浏览，不必退回首页。
5. **朗读可用**：中/英文喇叭互斥、可点停、切场景自动停止，符合低龄「听名字」诉求。
6. **状态记忆正确**：回花园后分类筛选与列表滚动位置均恢复。
7. **健壮性**：控制台 0 报错，1180×820 下同样无溢出。

## 4. 发现与建议（交 PO）

### F1 [P1 · 问题] 分类筛选后卡片封面不跟随分类
- **现象**：在「树叶」「果实」分类下，含花朵的植物（如苹果、银莲花）封面仍显示**花朵照片**，与当前分类不符，孩子会困惑「这里明明是树叶，怎么是花」。
- **证据**：`pf-03-home-leaf`（树叶分类）、`pf-05-home-fruit`（果实分类）。
- **根因（初判）**：后端清单卡片封面固定按 `flower → leaf → fruit` 回退，未参考请求分类（`PlantService` 封面回退逻辑）。分类字段未参与封面选择。
- **建议**：请求带分类时，封面**优先取该分类对应部位的首图**；若无该部位再按 `flower→leaf→fruit` 回退；「全部」维持原回退。前端无需改动。
- **影响**：纯后端展示逻辑，不影响契约与语料。

### F2 [P1 · 小微优化] 横屏详情图片偏小、左右留白多
- **现象**：横屏下图片仅 349px（占视口宽 34%），而内容区实际可用高度对应约 414px，存在约 65px 死区；画面重心偏小、留白明显。
- **证据**：`pf-04-detail-immersive`、`pf-12-detail-1180x820`。
- **根因（初判）**：横屏样式将图片宽度固定为容器 40%，未随可用高度放大。
- **建议**：横屏图片宽度上限由 40% 提升至约 48%，让图片贴近可用高度；改后须实测长文案（杜鹃花）不溢出（文字区已有内部滚动兜底）。
- **影响**：仅样式，不涉结构。

### F3 [P1 · 较大 → 建议排后续 Sprint] 首页「全部」一次渲染 100 张卡片
- **现象**：首页文档高度达 8634px，需长距离滚动才能看到后段植物；当前仅图片懒加载，无分页或滚动增量加载。
- **证据**：`pf-01-home-all`（首屏仅见 8 张）。
- **对照**：PRD §4.1 要求「植物总数超过一屏需支持翻页或滚动加载」。
- **建议**：纳入后续 Sprint 做滚动增量加载（首屏 + 分段加载），兼顾性能与「一直往下看」的连续性。
- **影响**：前端为主，属结构性改动，非小微。

### F4 [P2 · 小微优化] 卡片次级文字（拼音 / 英文）14px 偏小
- **现象**：卡片上拼音与英文字号 14px，横屏平板上偏小，孩子凑近才看得清。
- **证据**：`pf-01-home-all`、`pf-11-home-1180x820`。
- **建议**：卡片拼音 / 英文由 14px 调至 16px，与整体大字号风格更一致。
- **影响**：仅样式。

### F5 [P2 · 小微优化] 首页缺少「共 N 种」或滚动提示
- **现象**：首页没有植物总量提示，也没有「向下可看更多」的暗示，孩子/家长不易预期还有多少内容。
- **建议**：分类筛选旁显示「共 N 种」；或在列表顶部加轻量滚动提示（可与 F3 合并考虑）。
- **影响**：前端轻量改动。

### F6 [P2 · 并入 F2] 横屏头部信息区偏高
- **现象**：横屏下名称 + 拼音 + 英文 + 喇叭的头部区块约 190px，占用垂直空间偏多，进一步挤压图片。
- **建议**：与 F2 一并处理——收紧头部上下留白或字号（在可读前提下），把空间让给图片。
- **影响**：仅样式，建议并入 F2 一起验证。

## 5. 建议优先级汇总（供 PO 裁决）

| 编号 | 名称 | 类型 | 建议优先级 | 建议去向 |
|---|---|---|---|---|
| F1 | 封面不跟随分类 | 问题 | P1 | 本 Sprint 修复 |
| F2 | 横屏图片偏小 | 小微优化 | P1 | 本 Sprint 采纳 |
| F3 | 首页无加分页/增量加载 | 较大 | P1 | 排后续 Sprint |
| F4 | 卡片次级文字 14px | 小微优化 | P2 | 本 Sprint 采纳 |
| F5 | 首页无「共 N 种」提示 | 小微优化 | P2 | 并入 F3 或后续 |
| F6 | 横屏头部偏高 | 小微优化 | P2 | 并入 F2 |

**PF 总体意见**：产品主路径已经顺畅、可玩性好，Sprint 6 修复经实测有效。当前最值得优先处理的是 **F1（内容一致性）** 与 **三处小微优化（F2/F4/F6）**——改动小、收益直接；**F3（首页加载策略）** 是结构性问题，建议单列后续 Sprint 规划。
