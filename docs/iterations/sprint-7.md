## 迭代范围
1. **EX-1（F1，P1 · 问题）**：分类列表下卡片封面未跟随分类——「树叶 / 果实」分类中含花朵的植物仍显示花朵照片。改为请求带分类时封面优先取对应部位首图，缺失则回退。
2. **EX-2（F2+F6，P1 · 小微）**：iPad 横屏详情图片偏小、留白多（349px vs 可用 414px）；头部信息区偏高。放大图片、收紧头部。
3. **EX-3（F4，P2 · 小微）**：首页卡片拼音 / 英文字号 14px → 16px。

## 验收标准（Sprint 7 Definition of Done）
1. PRD §12.4 增量验收标准 20~22 逐条通过。
2. EX-2 在 1024×768 与 1180×820 下实测：图片显著增大、留白减少，长文案（杜鹃花）不溢出；页面级溢出仍为 0、内容区不可滚动（Sprint 6 约束不回归）。
3. EX-1 分类语义正确：「树叶 / 果实」分类下含花朵的植物封面与该分类一致；「全部」仍沿用原回退顺序；接口契约与语料不变。
4. 既有 TC 全量不回归（含 US-6 / US-7 与 Sprint 6 无滚动断言）。
5. 后端 `mvn test` + 前端 `npx vitest run` + `vite build` + `docker compose` 健康与两次导入幂等 + `npx playwright test` 全部退出码 0；全绿后 QA 放行，Master 执行 commit。

## 风险与依赖
| 风险 | 应对 |
|---|---|
| EX-1 改动封面选择会触及既有后端断言（如「树叶分类下银杏取叶」用例） | 先核对 `PlantApiIntegrationTest` 相关断言，按新语义更新；「全部」回退链保持不变，影响面限于带分类请求 |
| EX-2 放大图片可能重新引入横屏水平溢出（Sprint 6 刚消除的 87px） | 仅调整图片宽度上限，保持 `.part-content` 吸收剩余宽度；实测 1024×768 与 1180×820 无水平溢出 |
| EX-2 收紧头部可能影响长文案可读性 | 收紧幅度以「长文案仍完整可读」为底线；文字区内部滚动兜底保留 |
| 自动化环境无法复现 iPad Safari 真机观感 | 以度量口径验收（图片像素尺寸变大、留白减少、无溢出）；真机观感由人工在 iPad 抽验 |
| F3（首页加载策略）/ F5（数量提示）未纳入本 Sprint | 记录于裁决文档，由 Master 另立后续 Sprint 规划，不在本 Sprint 阻塞 |
