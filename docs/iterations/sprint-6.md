## 实测根因（Playwright，2026-10-17）
| 视口 | 页面级溢出 | 内容区溢出 |
|---|---|---|
| 1024×768（iPad 横屏） | 0 | **78px** |
| 768×1024（iPad 竖屏） | 0 | **130px** |
| 1180×820（iPad Air 横屏） | 0 | 59px |
| 820×1180（iPad Air 竖屏） | 0 | 17px |

- 溢出全部来自图片固定视角高度（横屏 `.part-img` 为 `64vh` = 492px，超过横屏内容区可用高度 446px）。
- 文字列实测最高约 397px，在横屏可用高度内可完整放下；竖屏可用高度 702px 亦大于最长文字。
- 「滚动退出全屏」机制：内容区可滚动 → 滚到边界后滚动链式传递至页面 → iPad Safari 在页面滚动时退出全屏。

## 风险与依赖
| 风险 | 应对 |
|---|---|
| 「滚动后退出全屏」在 headless Chromium 无法复现（iPad Safari 专有行为） | 以机制消除代替复现：容器脱离文档流 + `overscroll-behavior` 阻断链式滚动 + 内容区不可滚动，使「滚动退出全屏」的前提不复存在；真机行为由人工在 iPad 上抽验 |
| 图片自适应收缩后视觉占比变小 | 仅在空间不足时收缩，横屏空间充足时图片不受影响；竖屏以「图片可完整显示、文字不被裁切」为优先 |
| 极长文案在极端小屏放不下 | 兜底：仅文字卡片内部滚动，且 `overscroll-behavior: contain` 保证不传递到页面 / 全屏 |
| `position: fixed` 影响返回首页滚动位置恢复（TC-39） | 首页滚动位置由 HomePage 自行记录与恢复，与详情容器定位无关；门禁中显式回归 TC-39 |
| 既有断言依赖 `height: 100dvh` | 门禁同时回归 TC-38 / TC-40（页面级溢出 ≤1 断言在修复后更严格成立） |

## 迭代回顾
- 本轮为缺陷修复，未新增用户故事；PRD 增量 v1.3（§11）记录现象、实测根因与决策。
- 经验：把「沉浸式整屏」交给 `position: fixed; inset: 0` 比 `height: 100dvh` 更稳，可彻底消除动态视口与滚动链式传递带来的边界问题；图片尺寸应使用「按剩余空间自适应」而非写死 `vh`。
