## 风险与依赖
| 风险 | 应对 |
|---|---|
| 自动化环境无真实语音能力 | jsdom / headless Chromium 下 `speechSynthesis` 可能缺失：单测用 mock 注入；E2E 先 stub `window.speechSynthesis` 再断言喇叭存在与点击后调用发生，不依赖真实音频 |
| 系统语音包缺失（尤其中文 voice） | 属浏览器能力边界：无可用语音时不渲染喇叭，验收以「点按触发朗读调用」为准；真机音质由人工抽验 |
| iPad Safari 对语音播放的用户手势要求 | 由点击喇叭的用户手势直接触发 `speak`，符合浏览器策略 |
| 全屏态下按钮层级与遮挡 | 喇叭位于名称行内、沿用 `.imm-topbar` / `.detail-body` 层级，不遮挡 Sprint 4 的两侧切换按钮与全屏按钮 |
| 门禁受影响用例 | `frontend/src/__tests__/PlantDetailPage.test.jsx` 需注入 `speechSynthesis` mock 并新增断言；`e2e/` 需新增喇叭用例 |
