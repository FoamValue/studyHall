1. 语料校验：`OK total=250`，分类 6（flower/leaf/fruit/animal/insect/dinosaur），且 plants/animals/insects/dinosaurs 计数分别为 **100/50/50/50**；新增条目 `categories` 与 `parts` 键一致（单键板块键 = 分类 code）。
2. 图片资产齐备：`/images/animals/*.jpg` 50 张、`/images/insects/*.jpg` 50 张、`/images/dinosaurs/*.jpg` 50 张（恐龙一律**完整骨架化石**）；图片合计 `.jpg` **356** 张（plants 206 + 50×3）。
3. 音频资产齐备：`/audio/{id}-zh.m4a` 与 `/audio/{id}-en.m4a` 对**全部 250 条**存在（合计 500 个 `.m4a`）；缺失则导入校验报错。
4. 文案合规：新增条目 `description` ≤80 字且**无拉丁字母**；`allusion.text` ≤60 字、`allusion.explain` ≤50 字；单键板块 `allusion.source` 可选（沿用 §18 口径）。

6. 前端行为不回归：板块导航切换、单图详情（无部位切换）、音频喇叭（有音频渲染、缺失不渲染）、增量加载与「共 N 种」总量提示对 50 种板块成立（首屏 16 + 滚动步进 16）。
7. 既有 v1.0~v2.4 全部验收项（§7、§9.4、§10.4、§11.4、§12.4、§13.5、§14.5 26~33、§15.5 34~40、§16.5 41~47、§17.5 48~52、§18.5 53~57）**不回归**；植物板块 100/53/100/53 计数与资产不变。

**门禁证据（2026-10-18）**：语料/资产校验 `total=250`（plant100/animal50/insect50/dinosaur50）/ `flower=53 leaf=100 fruit=53` / 分类 6 / 图片 `.jpg` **356** / 音频 `.m4a` **500**；后端 `mvn test` 退出码 0（**21 用例**，后端零改动）；前端 `npx vitest run` **73/73**、`vite build` 退出码 0；`docker compose up -d --build` 重建后 `/api/health=UP`；两次导入各写入 250 条（import_log 4680→**5180**，门禁窗口 delta **+500 = 2×250**；Mongo **250 条目 / 6 分类**；导入后立即 `redis sh:*` = 0）；API 计数 all=250 / plant=100 / animal=50 / insect=50 / dinosaur=50 / flower=53；`npx playwright test` **56/56**（既有 52 + TC-130~TC-133）。

**问题与改进**：
- **D14-1（测试缺陷，已修复）**——TC-130 在「动物 → 昆虫」切换时失败：两板块总量文案同为「共 50 种」，上一板块 50 卡在 `setPlants(null)→新数据到达` 的竞态窗口内残留，使 `toHaveText` 与 `loadAllCards`（哨兵消失 + 卡数 50）双双早退，误判新板块已加载完。用例改为「切板块后先等该板块首屏专属首卡出现，再滚动加载」，末位断言改用 `.plant-card-zh` 文本定位。**仅测试层改动，无产品代码/契约变更。**
- **D14-2（流程缺陷，已修正）**——门禁第 0 步校验时误触发 1 次导入（+250），使 import_log 基线由 4430 抬升至 4680；已在用例手册如实修正口径（基线 4430 → 4680 → 门禁双导入 5180，判据为门禁窗口 delta +500）。

**经验沉淀**：内容扩容类 Sprint 中，多板块「总量文案相同」时，E2E 断言不可仅凭总量文案 + 全量加载助手判定板块切换完成，须以「该板块专属内容出现」作为切换完成信号（已记入 lesson）。

### 交付后图片体积微调（2026-10-18）

Sprint 14 交付后复核图片体积，发现 4 张新增动物图偏大（`peacock` 857KB、`gorilla` 509KB、`rhinoceros` 486KB、`leopard` 469KB，均超三板块均值 242KB 较多）。按 UI/内容产线微调处理：

- **`gorilla` / `rhinoceros` / `leopard`**：以 `djpeg | cjpeg -quality 70 -progressive` 原地重编码 → **438 / 417 / 404 KB**（均 <450KB），同名同路径、仍 **1600×1600 渐进式**，语料 JSON / 代码零改动。
- **`peacock`**：**保持原 q82（857KB）不改**——实测其羽纹细节密度高，即使降到 q40 仍需 460KB，无法在不显著损伤画质的前提下压至 450KB 以下；儿童认知场景**画质优先**，故保持原始编码。

**验证证据**：三板块 150 图全部 1600×1600（不合规 0）；nginx 重供新字节（`gorilla` 449044 / `rhinoceros` 427131 / `leopard` 414446 bytes，均 HTTP 200）；门禁按「图片字节与后端 / 前端单测无关」走精简验证路径——资产校验 + `docker compose up -d --build` 重建（health `UP`）+ `npx playwright test` **56/56** 全绿；后端 `mvn test` 21 用例与前端 `vitest` 73/73 不受图片字节影响，沿用 Sprint 14 门禁结果。
