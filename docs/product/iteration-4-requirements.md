## 一、迭代目标
把植物详情页从「只能回花园的终点页」升级为沉浸式连续浏览：进入后可在植物之间（左右滑 / 两侧大按钮 / 键盘 ←→）与部位之间（花/叶/果按钮）自由切换，支持系统全屏进出，返回首页后保住分类筛选与列表滚动位置。路由结构与首页保持不变。

## 二、角色问答记录

**【R】问：详情页需要「当前分类下的有序邻居列表」，但直接打开 `/plants/:id` 深链接时没有列表上下文，邻居按钮还能用吗？**
【PO】答：两条进入路径都必须可用：
- 从首页点卡片进入 → 沿用首页已有的列表数据（与当前分类一致）作为邻居来源，不重复请求；
- 直接输入 URL 进入 → 详情页按「全部」分类自行拉一次列表兜底，两侧按钮与键盘照常可用。
邻居只在「当前生效列表」内前后移动，不做跨分类跳转；列表为空或仅一株时，两侧按钮禁用（不隐藏，保持可见以免版式跳动）。

**【R】问：左右滑与「点部位按钮」会不会互相干扰？**
【PO】答：明确分工，同一手势不承担两种语义：**水平滑 = 换植物**，**点部位按钮 = 换部位**。滑动需超过水平位移阈值才触发换株，避免与纵向滚动/误触冲突。

**【R】问：换植物后，部位怎么处理？**
【PO】答：换到新植物后默认落在该植物实际存在的第一个部位（沿用现有 `flower→leaf→fruit` 顺序）；若新植物没有当前正在看的部位，也回落到其第一个部位。切回原植物不强制记住上次部位。

**【UI】问：沉浸式态的最小操作区包含哪些元素？**
【PO】答：自上而下：
- 左上「← 回花园」（保留原入口，文字与样式沿用 `.back-btn`）；
- 右上「全屏」（图标 + 文字，热区 ≥56px）；
- 两侧垂直居中「← 上一株」「下一株 →」大号按钮（热区 ≥56px，半透明底，不遮挡主体图片）；
- 底部中央沿用现有「花 / 叶 / 果」部位按钮组。
站点标题（拼音 + 中文大字 + 英文）在详情页隐藏，减少留白。全屏态保留同一套操作区。

**【UI】问：沉浸式态图片如何保证「完整不裁切 + 无页面级滚动条」？**
【PO】答：图片区按视口高度自适应（`object-fit: contain`，禁止裁切），文字信息在平板横竖屏下均需可见；若信息在极小高度下确实放不下（如矮横屏），允许该区域内局部滚动，但**页面级滚动条必须消除**。具体断点由 UI 定，验收以 PRD §9.4-7/11 为准。

**【J】问：邻居列表的顺序稳定吗？会不会同一列表两次请求顺序不同？**
【PO】答：不改后端契约。现有列表接口 `GET /api/plants?category=` 已按 `id` 升序稳定返回，邻居计算直接依赖该顺序即可；J-6 需在文档中确认排序依据与缓存策略（复用 `sh:plants:list:*`），不新增接口。

**【R】问：全屏按钮在 iPad/Safari 行为不一致怎么办？**
【PO】答：全屏是增强项。不支持 Fullscreen API 的环境下按钮隐藏或降级为提示，沉浸式态的全部功能（换株、换部位、回花园）不受影响；Esc 与「退出全屏」按钮都需能回沉浸式态，且不丢失当前植物、部位。

**【QA】问：三通道（滑动 / 按钮 / 键盘）行为一致如何自动化验收？**
【PO】答：E2E 在同一起点分别用三种方式切到相邻植株，断言最终落到**同一株**；再用「首尾循环」用例从列表末尾切到下一株应回到第一株、反向同理。滑动在 Playwright 中用 `mouse` 拖拽序列模拟。

**【QA】问：返回首页的记忆如何验收？**
【PO】答：E2E 断言「首页 → 选分类 → 滚动列表 → 进详情 → 回花园」后，分类按钮仍选中原分类、列表滚动位置在合理误差内恢复（不回到顶部）。深链接进入后返回，按默认「全部」处理，不视为失败。

与 sprint-4.md「验收标准」5 条 + PRD §9.4 增量验收标准 6~11 一致，QA 据此编写测试用例（编号接 Sprint 3 手册，TC-28 起）。

## 四、非目标（本迭代不做）
- 后端接口契约变更（不新增邻居接口、不改列表返回结构）
- 手势缩放（pinch-zoom）图片、拖拽图片
- 详情页跨分类连续翻（只在当前生效列表内循环）
- 手机专项适配、TTS 朗读、问答、进度记录（PRD 已取消或暂缓）
- 首页信息架构调整（保留站点标题、分类筛选与网格）
