## 1. 产品概述
- **定位**：面向幼儿园学龄儿童（约 3–6 岁）的**自然认知图鉴**网站（v2.0 升级，2026-10-17 人工确认），帮助孩子认识现实中的**植物、动物、昆虫、恐龙**——植物按「花朵、树叶、果实」等部位认知；动物 / 昆虫 / 恐龙以一张写实图 + 一条小知识认知（无部位切换）。详见 §14。
- **形态**：网页，平板浏览器打开即用；电脑次之；手机暂不作为目标设备（不保证体验）。
- **使用方式**：无需登录、无进度记录，打开即看。

## 3. 用户故事
- **US-1** 作为孩子，我可以在首页按「花朵 / 树叶 / 果实」等分类筛选，找到想看的植物。
- **US-2** 作为孩子，我可以在植物列表中点选一张植物卡片，进入它的详情页。
- **US-3** 作为孩子，我可以在详情页点击「花 / 叶 / 果」部位标签，切换查看不同部位。
- **US-4** 作为孩子，我看到的每个部位都有：彩色简笔画（或真实照片）、拼音+中文名、英文名+音标、低龄化中文说明、相关典故。
- **US-5** 作为维护者，我可以把植物信息和真实图片交给 AI 工具，由 AI 更新到内容库，无需操作后台界面。
- **US-6**（v1.1 增量）作为孩子，我可以在植物详情里沉浸式、全屏地看图，用左右滑动或两侧大按钮直接翻到上一株 / 下一株，不用退回首页重新点选。详见 §9。
- **US-7**（v1.2 增量）作为还不识字的孩子，我可以点植物名称旁边的小喇叭，听它把中文名或英文名读出来，跟着把名字学会。详见 §10。
- **US-8**（v1.5 增量）作为孩子，我在「花朵 / 树叶 / 果实」分类下看到的卡片名字和点进去的详情默认部位，都跟我在看的这一分类一致，不会出现「名字说苹果、图是叶子、点进去却是花」的混乱。详见 §13。
- **US-9**（v2.0 增量）作为孩子，我可以在首页切换「植物 / 动物 / 昆虫 / 恐龙」板块，在植物板块里还能按「花朵 / 树叶 / 果实」细分，找到我想看的生物。详见 §14。
- **US-10**（v2.0 增量）作为孩子，我在「动物 / 昆虫 / 恐龙」板块点开一张卡片，看到的是一张清楚的写实大图和一条小知识，不用再切花 / 叶 / 果。详见 §14。
- **US-11**（v2.0 增量）作为孩子或家长，我点名称旁的小喇叭就能听到标准的中文 / 英文读音，且**换任何设备听起来都一样**（预生成音频）。详见 §14。
- **US-12**（v2.0 增量）作为内容维护者，我可以给每个条目设置排序号（依据分布区域、季节、常见度等），列表按我设定的顺序稳定展示。详见 §14。

## 4. 功能需求
### 4.1 首页 — 分类筛选
- 提供植物分类筛选入口（首批：花朵 / 树叶 / 果实，具体分类以内容库实际数据为准，需支持后续新增分类）。
- 筛选后展示该分类下的植物网格列表：植物图片缩略图 + 中文名 + 拼音 + 英文名。
- 提供「全部」选项；植物总数超过一屏需支持翻页或滚动加载。

### 4.2 植物详情页 — 部位切换
- 单页展示一种植物，通过部位标签（花 / 叶 / 果）点击切换，一次只展示一个部位。
- 每个部位内容包括：该部位图片（简笔画，可附真实照片）、该部位的三语名称、低龄化中文说明、典故引用。
- 植物若缺少某部位内容，则不显示对应标签。

### 4.3 内容数据格式（约束性需求）
- 结构化存储，便于 AI 读写与后续扩容；具体 schema 由开发设计阶段定义，须满足：
  - 一种植物包含多个部位（花/叶/果），每个部位可有多张图片；
  - 支持简笔画与真实照片两种图片类型；
  - 支持分类字段扩展；
  - 拼音、音标作为独立字段存储（不做运行时自动标注依赖）。

### 4.4 内容更新通道（AI 接管）
- 不开发管理后台 UI、不设管理员账号。
- 内容更新方式：人工向 AI 工具提供植物信息与真实图片 → AI 依照内容格式约定，通过可执行的导入方式（如导入脚本/数据文件）更新内容库。
- 内容库更新后网站即可展示新增植物，无需改代码。

## 5. 非功能需求
- **低龄化 UI**：大按钮、大字号、色彩明快、触屏友好；点击热区足够大。
- **响应式**：平板优先，电脑次之。
- **性能**：图片懒加载；部位切换响应即时（≤1s）。
- **安全**：前台纯只读、无用户输入；无个人信息收集。
- **文案规范**：短句、常用字、口语化、无生僻专业术语；典故配一句低龄化白话解释。

## 7. 关键验收标准
1. 平板浏览器打开即可使用，全程无注册、无登录。
2. 从打开网站到看到任意一种植物详情，操作不超过 3 次点击。
3. 每种植物的部位（花/叶/果）切换展示正确，内容包含图片、三语名称、说明、典故。
4. 内容库数据格式支持新增一种植物（扩容演练：AI 导入一种新植物后网站可直接展示）。
5. 文字内容符合低龄化文案规范。

## 9. 增量 v1.1（2026-10-17）— 全屏连续浏览（US-6）

### 9.1 背景与目标
- **痛点（人工提出）**：详情页只提供「← 回花园」一个出口，想换一株植物必须退回首页重新点选，连续看图鉴的路径被打断，使用很不方便。
- **目标**：把详情浏览变成沉浸式、连续的体验——进入后可以一直在植物之间、部位之间切换，无需退回首页。

### 9.2 需求决策记录（与人工澄清结论，2026-10-17）
| 事项 | 结论 |
|---|---|
| 全屏形态 | **A+B**：默认进入沉浸式详情页（图片占满视口、隐藏站点标题与多余留白，仅保留最小操作区）；另设「全屏」按钮触发系统 Fullscreen API，Esc 或退出按钮回到沉浸式态 |
| 快速切换对象 | 植物之间 + 部位之间，**两者都要** |
| 手势分工 | **左右滑 = 换植物**；**点部位按钮 = 换花/叶/果**（同一手势不承担两种语义） |
| 切换范围 | 仅限当前筛选分类内（如只看「果实」则只在果实内翻） |
| 循环方式 | **首尾循环**：翻到名单末尾自动接回第一个，反向同理 |
| 显式控件 | 沉浸式态两侧固定大号「← 上一株 / 下一株 →」按钮（热区 ≥56px）；同时支持键盘 ← / → |
| 返回与记忆 | 保留「回花园」入口（沉浸式态与全屏态均可退）；返回首页后保住此前的分类筛选与列表滚动位置 |

### 9.3 功能需求
- **沉浸式详情页**：单屏呈现当前部位大图 + 该部位三语名称 + 低龄化说明 + 典故；无页面级滚动条，图片完整不裁切。
- **植物切换**：左右滑动 / 两侧按钮 / 键盘 ← → 三种通道行为一致；切换前相邻植物的数据与图片已预加载，切换过程无白屏。
- **部位切换**：沿用现有「花 / 叶 / 果」按钮语义，仅显示该植物实际存在的部位。
- **系统全屏**：「全屏」按钮进入浏览器全屏；Esc 或退出按钮返回沉浸式态，当前植物、部位与浏览位置不丢。
- **路由与首页不变**：仍为 `/` 首页、`/plants/:id` 详情；首页保留并继续作为入口。
- **状态记忆**：从详情返回首页后，恢复此前的分类筛选与列表滚动位置。

### 9.4 验收标准（增量，编号接 §7）
6. 从任一植物详情，≤1 次操作即可切到相邻植物，切换过程无白屏。
7. 沉浸式态：图片完整不裁切，且无页面级滚动条。
8. 点「全屏」进入系统全屏；Esc 或退出按钮可回沉浸式态，退出后浏览位置不丢。
9. 左右滑 / 键盘方向键 / 两侧按钮三种方式换植物，行为一致（含首尾循环、限当前分类）。
10. 所有可操作元素热区 ≥56px，符合现行 UI 规范。
11. 平板横竖屏、1024×768 及 iPad 常见尺寸下均正常。

## 10. 增量 v1.2（2026-10-17）— 语音朗读（US-7）

### 10.1 背景与目标
- **痛点（人工提出）**：目标用户 3–6 岁还不识字，看得到植物名却读不出来，身边没有大人时无法知道怎么念、更记不住名字。
- **目标**：在详情页为中文名与英文名各配一个朗读喇叭，点一下就能听到标准发音，帮助孩子把名字读出来、跟着学会。

### 10.2 需求决策记录（与人工澄清结论，2026-10-17）
| 事项 | 结论 |
|---|---|
| 朗读对象 | **喇叭只读名称本身**：中文喇叭读中文名，英文喇叭读英文名；拼音、部位名、说明、典故一律不读 |
| 音源方案 | **浏览器原生语音合成**（Web Speech API 的 `SpeechSynthesis`）：不预生成音频文件、不新增后端接口 |
| 位置与形态 | 中文喇叭贴中文名右侧、英文喇叭贴英文名右侧；热区 ≥56px；播放中高亮并切为「停止」图标 |
| 播放控制 | 点击播放、再点停止；中/英两个喇叭互斥、不重叠；切换植物、切换部位、离开详情页时自动停止 |
| 适用范围 | 仅详情页（含沉浸式态与全屏态）；首页列表卡片不放喇叭 |
| 语速 | 中/英均 `0.8×`；浏览器不支持语音合成时喇叭不渲染（优雅降级） |
| 版本 | 新增 **US-7**，v1.2 增量 |

### 10.3 功能需求
- **中文名称喇叭**：点按朗读中文名（如「银杏」）。
- **英文名称喇叭**：点按朗读英文名（如「Ginkgo」）；若某植物无英文名，则不渲染该喇叭。
- **互斥播放**：任一时刻最多一个喇叭在播放；点另一个会先停止当前再播放新的。
- **自动停止**：切换植物、切换部位、点「回花园」离开详情、进入 / 退出全屏时，正在进行的朗读立即停止。
- **优雅降级**：浏览器不支持 `SpeechSynthesis` 时喇叭不渲染，页面其余功能完全不受影响。
- **不改动内容语料与后端**：纯前端能力，`GET /api/plants`、`GET /api/plants/{id}` 契约与语料结构均不变。

### 10.4 验收标准（增量，编号接 §9.4）
12. 详情页中文名、英文名各有一个朗读喇叭，点一下能听到对应语言的名称发音（以浏览器原生语音能力为准）。

## 11. 增量 v1.3 — 缺陷修复：详情页整屏不滚动（US-7 回归）
| 项 | 内容 |
|---|---|
| 提出人 | 人工（2026-10-17） |
| 目标设备 | **iPad 浏览器（Safari）** 为验收基准设备 |
| 现象 | 进入详情页（沉浸式态 / 全屏态）后仍有纵向滚动条；滚动该区域会带动页面滚动，进而使 iPad Safari 退出全屏 |
| 版本 | v1.3 增量；对应 Sprint 6 |

### 11.1 背景与目标
Sprint 4 将详情页升级为「沉浸式全屏浏览」，其设计约定为「页面级不滚动、内容区内部可滚动」。该约定在 iPad Safari 上产生两个问题：内容区出现纵向滚动条（与「沉浸式全屏」的观感不符），且滚动行为会触发页面滚动，导致浏览器退出全屏。

**目标**：详情页在 iPad 横屏 / 竖屏下均**整屏呈现、任何位置都不出现纵向滚动条**；且**不发生任何页面级滚动**，从而不再因滚动退出全屏。图片保持完整不裁切、文字完整可读。

### 11.2 缺陷记录与实测根因（2026-10-17，Playwright 实测）
| 视口 | 页面级溢出 | 内容区溢出 | 归因 |
|---|---|---|---|
| 1024×768（iPad 横屏） | 0 | **78px** | 图片固定 `64vh`（492px）超过内容区可用高度（446px） |
| 768×1024（iPad 竖屏） | 0 | **130px** | 图片 `44vh` + 文字合计超出可用高度 |
| 1180×820 / 820×1180 | 0 | 59px / 17px | 同上 |

- 结论：溢出**全部来自图片的固定视角高度**；文字列实测最高约 397px，在横屏可用高度内可完整放下。
- 「滚动后退出全屏」的机制为：内容区可滚动 → 滚到边界后滚动链式传递到页面 → iPad Safari 在页面滚动时退出全屏。

### 11.3 修复方案（决策）
| 事项 | 决策 |
|---|---|
| 容器定位 | 沉浸式容器改为**脱离文档流并铺满视口**（`position: fixed; inset: 0`），使页面高度恒等于视口、永不产生页面级滚动 |
| 内容区滚动 | 内容区**不再滚动**（`overflow: hidden`）；滚动链式传递被阻断（`overscroll-behavior: none / contain`） |
| 图片尺寸 | 图片不再写死视角高度，改为**按剩余空间自适应收缩**（保持 `object-fit: contain` 完整不裁切） |
| 文字兜底 | 仅当极长文案在极端小屏放不下时，允许**文字卡片内部**滚动，且不得传递到页面 / 全屏 |
| 不改变 | 路由、后端契约、语料结构、部位切换、换株、全屏、语音朗读行为全部保持不变 |

### 11.4 验收标准（增量，编号接 §10.4）
17. 在 iPad 横屏（1024×768、1180×820）与竖屏（768×1024、820×1180）下，详情页沉浸式态与全屏态**均无纵向滚动条**：页面级溢出为 0，且内容区不可滚动。
18. 详情页内**不发生页面级滚动**：滚动操作不会使 `window.scrollY`（或文档滚动位置）变化，因而不会导致 iPad Safari 退出全屏。
19. 修复后图片仍**完整不裁切**（`object-fit: contain`）、文字完整可读；既有 US-6 / US-7 行为（连续换株、全屏进出、返回首页保住分类与滚动位置、语音朗读）全部不回归。

### 11.5 非目标（本增量不做）
- 不重做详情页视觉版式，仅在必要范围内调整尺寸与溢出策略。
- 不新增滚动容器、不做内容分页 / 折叠。
- 不做手机端专项适配。

### 14.4 功能需求

#### 14.4.1 板块与分类体系（两层模型）
- **板块（4 个，顶层）**：**植物 / 动物 / 昆虫 / 恐龙**，各板块独立入口，首页顶层可切换。
- **植物板块内分类**：延续现有「花朵 / 树叶 / 果实」（+「全部」）筛选，沿用 `categories.json` 数据驱动机制，**不改**既有分类展示与卡片行为。
- **动物 / 昆虫 / 恐龙板块内**：**不再细分分类**，板块即浏览粒度，「全部」即该板块全量列表。
- **元数据扩展（数据驱动，不改代码枚举）**：在 `content/categories.json` 新增 `animal` / `insect` / `dinosaur` 三条分类（`order` 顺接 4 / 5 / 6），并区分「板块」层级；`GET /api/categories` 契约向后兼容扩展。
- **首页结构**：板块切换 + （植物板块下的）分类筛选 + 卡片网格；从详情返回仍记忆此前所在板块与（植物板块下的）分类及滚动位置。

#### 14.4.2 内容模型（方案 B 落地约束）
- **植物条目**（现状不变）：`parts` 多部位（`flower` / `leaf` / `fruit`），每部位 = 三语名称 + 图片 + 低龄化说明 + 可选小知识。
- **动物 / 昆虫 / 恐龙条目**：**单图模型** —— 三语名称 + **1 张主图** + 1 段低龄化说明 + 1 条小知识；**无部位切换按钮**。
  - **PO 拟定实现约束**（细节由 J / R 在《开发设计文章》定稿）：优先**复用 `parts` 结构以单键承载**（键与板块对应，如 `animal` / `insect` / `dinosaur`），或新增独立单图字段；
  - **硬约束**：不得改动既有植物 `parts` 结构与图片路径、不得导致既有 100 种植物数据重导、不得破坏 US-3 / US-6 / US-8 既有行为。
- 后端既有的「部位固定顺序、分类合法性校验、封面回退」等硬编码需**向后兼容扩展**以容纳新键与新分类。

#### 14.4.3 图片资产口径
- **归档与命名**：按板块分目录，如 `frontend/public/images/{section}/`；动物 / 昆虫 / 恐龙单图命名由设计阶段定稿（拟定 `{id}.jpg`）；**植物维持** `/images/plants/{id}-{part}.jpg` 不变。
- **图片类型语义**：`images[].type` 允许 `photo`（写实照片）与新增的 **`restore`（写实复原图）** 两值；恐龙骨架化石图按素材实际来源取 `photo`（真实化石拍摄）或 `restore`（写实复原渲染）。
- **清晰度与形态**：单图 JPG，长边建议 ≥1024px，与现有植物图展示规格一致；沿用懒加载。
- **数量级**：上限 400 条目 → 既有植物 206 张 + 动物 / 昆虫 / 恐龙各 ≤100 ≈ **≤500 张**。

#### 14.4.4 小知识卡片（替代「典故」）
- **统一卡片**：标题「小知识」+ 正文（≤60 字）+ 可选出处 + 白话解释（≤50 字）。
- **植物**：沿用既有古诗典故内容（出处保留），仅卡片**称谓**由「典故」改为「小知识」（组件复用）。
- **动物 / 昆虫 / 恐龙**：内容取自**冷知识 / 习性 / 分布位置 / 季节**等；出处可缺省。
- **缺省规则**：条目无小知识内容时**不渲染**卡片（沿用现有「无典故不渲染」逻辑）。
- 文案仍须符合 §5 低龄化规范（短句、常用字、口语化、无生僻术语）。

#### 14.4.5 三语名称与音频朗读（预生成音频 .m4a）
- **名称信息**：每条目 = 中文名 + 拼音 + 中文读音；英文名 + 国际音标 + 英文读音（英文名缺失时仅中文）。
- **音频形态（格式已裁决）**：读音由**预生成音频文件**承载，**格式统一为 AAC（`.m4a`）**，每条目 **2 个音频**（中 / 英各一），随内容资产落盘并纳入导入校验；路径 / 命名由设计阶段定稿（拟定 `/audio/{id}-zh.m4a`、`/audio/{id}-en.m4a`）。
- **格式裁决依据（2026-10-17 实测 + 人工裁决）**：本机无 `ffmpeg` / `lame`，macOS 自带 `afconvert` 不支持 mp3 编码；系统 `say`（中文 `Tingting` / 英文 `Samantha`）可直接输出 AAC `.m4a`。人工裁决**采用 AAC `.m4a`**，不引入 mp3 编码链。
- **播放交互**：沿用 §10 既有约定 —— 喇叭贴名称右侧、热区 ≥56px、点击播放 / 再点停止、中 / 英互斥、切换植物 / 部位 / 离开详情 / 全屏进出时自动停止。
- **与 Sprint 5 的关系**：以 **预生成音频取代浏览器实时合成**，不再依赖设备语音包，**跨设备听感一致**；音频缺失时**不渲染**该喇叭（优雅降级，见 14.7-③）。
- **音频数量级**：上限 400 条目 × 2 ≈ **≤800 个音频文件**，分批生成（同 14.4.7）。

#### 14.4.6 排序（`sort`）
- **字段**：语料新增 `sort` 整数字段（每条目 1 个默认展示序）。
- **规则**：同一分类 / 板块内按 `sort` 升序；`sort` 相同或缺失时按 `id` 升序兜底，展示顺序**稳定可复现**。
- **排序依据**：分布区域（如「常见于中国北方」）、季节（花期 / 出现季节）、常见度等，由内容维护者据此给出 `sort` 数值。
- **顺带清技术债**：分类列表查询由「依赖 Mongo 自然序」改为**显式** `Sort.by(ASC, "sort", "id")`（§五 移交技术债）。
- **界面**：**不提供**用户可见排序控件（PO 建议，见 14.7-⑤）。

#### 14.4.7 内容规模与分批交付
- **目标规模**：板块各 ≤100 种（植物已 100 达标；动物 / 昆虫 / 恐龙各 ≤100）。
- **分批策略（PO 建议，见 14.7-⑦）**：Sprint 9 先交付**能力 + 试点内容** —— 板块导航、单图模型、小知识、音频机制**全量打通**，并以**每板块 10~20 种**试点内容通过验收；后续 Sprint **分批扩容至各 100 种**（每次扩容不改代码，仅走 §4.4 的 AI 导入通道）。
- **容量提示**：全量 400 条目的图片 ≈ ≤500 张、音频 ≈ ≤800 个文件，内容生产与 QA 校验按批次推进，避免单迭代过载。

## 20. 增量 v2.6（2026-10-18）— 产品定位升级：认知启蒙（英文字母 / 汉语拼音 / 数字 / 颜色）US-21~US-25

### 20.1 背景与目标
- **背景**：v2.5 已完成「自然认知」四板块（植物 / 动物 / 昆虫 / 恐龙，各含 50~100 条）。3–6 岁幼儿在认识自然之外，同样需要**字母、数字、颜色**等启蒙认知内容。人工（2026-10-18）裁定：产品定位升级为**「认知启蒙」**，在自然认知之外增设「认知启蒙」板块组。

### 20.3 用户故事
- **US-21**：作为家长/老师，我希望图鉴里除了动物植物，还能教孩子认字母、拼音、数字和颜色。
- **US-22**：作为幼儿，我希望一眼看到大写和小写字母在一起（Aa），跟着念出来。
- **US-23**：作为幼儿，我希望按顺序学会 a b c … z（汉语拼音）。
- **US-24**：作为幼儿，我希望从 0 数到 20，看到每个数字的样子和读法。
- **US-25**：作为幼儿，我希望认识红、黄、蓝等常见颜色，并知道它们的名字。

### 20.4 需求明细
- **20.4.1 首页与产品名**：站点更名为**「认知小图鉴」**；首页板块导航升级为**两大组**：`自然认知`（plant / animal / insect / dinosaur）+ `认知启蒙`（letter / pinyin / number / color），共 8 板块；二级分类筛选仅植物板块保留（不变）。
- **20.4.2 英文字母板块（section=`letter`）**：26 条，**大小写同卡**（示例卡「Aa」）；`sort` 1…26 按字母序；**无中英文名分野、无音标**。
- **20.4.3 汉语拼音板块（section=`pinyin`）**：26 条，a…z 按序；`sort` 1…26；**无中英文名分野、无音标**。
- **20.4.4 数字板块（section=`number`）**：21 条，**0…20**；`sort` 0…20 升序；保留中文名 / 拼音 / 英文名 / 音标（如 1「一 / yī / One / /wʌn/」）。
- **20.4.5 颜色板块（section=`color`）**：11 条，英文基础 11 色；`sort` 按基础色常见序；保留中文名 / 拼音 / 英文名 / 音标（如 red「红 / hóng / Red / /red/」）。
- **20.4.6 内容模型适配**（**关键**：本增量为**能力迭代**，非纯内容）：
  - `parts` 单键新增 `letter` / `pinyin` / `number` / `color` 四个键；
  - 字母 / 拼音条目**省略** `name.pinyin` / `name.en` / `name.ipa`；（主标题即符号本身）
  - 卡片与详情沿用单图模型，**无部位切换**（与动物 / 昆虫 / 恐龙一致）；
  - `allusion`（小知识）：四板块各条目**均需一条**（联想 / 常识型，如「A 像一座塔」「0 像鸡蛋」）。
- **20.4.7 图片资产**：每条 1 张 1600×1600 渐进式 `.jpg`（颜色为**纯色块卡**、数字为**大号数字 + 点数**、字母为**大小写字形卡**、拼音为**字形卡**）；风格口径由 UI 出规范。
- **20.4.8 音频资产**：字母 = 英文读音（字母名，如 A /eɪ/，**单语音频**）；拼音 = 汉语读音（**单语音频**）；数字 / 颜色 = zh / en 各一（`/audio/{id}-zh.m4a`、`/audio/{id}-en.m4a`），沿用 `say -v Tingting`(zh) / `Samantha`(en) → AAC `.m4a`。
- **20.4.9 文案红线豁免**：字母 / 拼音板块的条目**本体即为拉丁字母**，其 `description`「无拉丁字母」红线**豁免**；数字 / 颜色板块仍沿用红线。

### 20.5 非目标（本增量不做）
