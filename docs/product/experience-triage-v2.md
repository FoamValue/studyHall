## 1. 裁决原则

- **需求落地缺口优先于纯观感优化**：声称已交付的称谓 / 能力若用户实际看不到，按问题处理而非优化。
- **小微优化优先**：改动小、风险低、孩子直接可感的项先落地。
- **已推迟过一次的项不再第三次顺延**：v1 已裁决「排后续 Sprint」而至今未排期的结构性项，本次必须给出排期。
- **内容口径变更另立议题**：涉及语料 / 资产 / 已冻结非目标（§14.6）的改动不塞进体验优化 Sprint。

## 4. 排期弹性说明（供 Master 参考）

- EX-4 与 EX-5 均为**小微改动**（一个组件 + 一个横屏样式分支），可独立交付、回归面窄，风险低。
- EX-6 为**结构性改动**，牵动首页列表渲染、分类筛选联动、滚动记忆与既有 E2E 列表计数断言。
- 若 Sprint 10 开发中 EX-6 回归面超预期，**允许 Master 将 EX-6 顺延至 Sprint 11**，先交付 EX-4 / EX-5；此顺延不视为「第三次推迟」，但须在迭代回顾中记录原因。

## 5. 风险与约束

- **EX-4**：可见标题须与卡片正文层级协调（正文 22px / 解释 18px），不得挤占横屏竖向空间导致长条目不溢出约束失效（1024×768 与 1180×820 双尺寸实测）。
- **EX-5**：改动**仅限**单图板块（`parts` 单键，即 animal / insect / dinosaur）的横屏分支；**植物详情（三部位）版式必须保持现状不回归**；改后须实测长文案条目不溢出，且详情页页面级溢出仍为 0（受 Sprint 6 约束）。
- **EX-6**：分段加载不得改变「列表顺序 = `sort` ASC + `id` ASC」语义，不得破坏回花园的滚动位置记忆；「共 N 种」文案口径须与筛选态一致（植物「全部」= 100，分类态 = 该分类计数，动物 / 昆虫 / 恐龙板块 = 板块计数；动物 / 昆虫 / 恐龙因仅 10 种可**不做**分段加载，但总量提示可统一展示）。
- 三项均**不改**后端接口契约、语料结构、路由与既有 US-6 / US-7 / US-8 行为。
