## 一、冻结口径（Q1~Q6，PO 裁决 P20，不许再变更）

| 编号 | 问题 | 冻结结论 |
|---|---|---|
| Q1 | 重绘范围 | 仅数字板块 21 张图：`frontend/public/images/numbers/number-0.jpg … number-20.jpg`，同名同路径覆盖；其余 427 张条目图与 8 张封面不动 |
| Q2 | 画面规格 | 底色纸白 `#FCF7ED`；大号阿拉伯数字深棕墨 `#3A2A22`、圆润粗体、居中偏上（0 整幅居中）；计数物为朱砂小苹果（果身 `#B45B3E` 系 + 深色小叶 `#8A3E27`，圆润简笔扁平风），数量 = 数值，0 无计数物 |
| Q3 | 分组规则 | 每排最多 5 个，自上而下降序填满、末排为余数、每排水平居中：1~5 单排；6~10「5+余数」两排；11~20 按 5 列网格（11~15 为 5+5+余数三排，16~20 为 5+5+5+余数四排） |
| Q4 | 尺寸与构图 | 苹果随数量自适应缩放（1 排 a=230 / 2 排 a=200 / 3 排 a=175 / 4 排 a=160，a=外接盒边长），单排最多 5 个不拥挤；整体构图居中、留白均匀 |
| Q5 | 实现方式 | **脚本确定性绘制**（SVG→JPG，沿用 `generate-covers.mjs` 的 Playwright 截图 + cjpeg q82 渐进式通道），数量零误差；字体用系统圆润粗体回退链，若渲染效果差允许数字改 SVG path 自绘，但必须保证字形清晰正确 |
| Q6 | 零改动红线 | 前后端产品代码、语料 JSON、路由、接口契约、音频一律不动；仅 21 张图片资产变化 + 新增生成脚本 + 文档 |

## 三、验收标准（编号 94~97，冻结）

- **94**：21 张数字图按冻结规格重出——全部存在、1600×1600、渐进式 `.jpg`、体积合理（扁平色图小体积为正常）。
- **95**：每张计数物（小苹果）数量 = 卡片数值（number-0 无计数物），分组符合 Q3，无畸形、无错位、21 张风格一致。
- **96**：大号数字字形清晰正确（0~20 阿拉伯数字无歧义），色值符合 U20-1（底 `#FCF7ED` / 数字 `#3A2A22` / 苹果 `#B45B3E` 系）。
- **97**：三层测试全绿（后端 28 / vitest 90 / E2E 86），无产品代码改动；导入幂等不回归。

## 四、风险与对策

1. **数量错误（最大风险）**：脚本循环确定性绘制 + R 逐张 Read 核验（至少 0/1/5/7/11/16/20），QA 门禁复核。
2. **字体渲染差**：Playwright+Chromium 渲染 + 系统圆润粗体回退链；抽看不合格则数字改 SVG path 自绘。
3. **既有测试受图片变化影响**：既有断言仅涉图片路径/尺寸/HTTP 状态，不涉图像内容；失败先判测试层口径，不改产品代码。
