## 二、角色问答记录（阶段 2）
### R ↔ PO
- **R-1 横屏图片放大到多少合适？** → PO：以「尽量贴近可用高度、留白明显减少」为目标，先取宽度上限约 **48%**；以 1024×768 与 1180×820 实测为准，若长文案溢出则回调。不设固定像素值。
- **R-2 头部要收紧到什么程度？** → PO：**在可读前提下**减少上下留白或适度收字号，把竖轴空间让给图片；底线是长文案（杜鹃花）仍完整可读、不溢出。
- **R-3 放大图片会不会又出现水平溢出（Sprint 6 刚消除的 87px）？** → PO：不允许回归。保持 `.part-content` 吸收剩余宽度；门禁须在 1024×768 与 1180×820 断言无水平溢出。
- **R-4 卡片字号改 16px 会撑坏布局吗？** → PO：仅次级文字（拼音/英文）字号变化，卡片高度由图片主导，可接受；门禁回归首页卡片浏览器截图与断言。
- **R-5 要不要顺带做首页加载优化（F3）？** → PO：**不做**，F3 另立后续 Sprint；本迭代严格限定 EX-1~EX-3。

### J ↔ PO
- **J-2 封面跟随分类怎么实现？** → PO：`getPlants(category)` 已带分类且缓存 key 已按分类区分，无需改接口；将分类透传到卡片生成，封面选择「以分类对应部位优先，缺失回退 `flower→leaf→fruit`」；分类为 `null/空`（全部）时保持原样。
- **J-3 缓存键要不要改？** → PO：**不改**。缓存 key 已按 category 区分（`sh:plants:list:{category|all}`），新语义天然随分类隔离。
- **J-4 既有断言怎么办？** → PO：核对并更新受影响的封面断言（如 TC-07 银杏在「全部」下仍回退到 leaf，保持不变；若新增/调整需按新语义更新）；同步更新 `docs/design/backend-design.md` 与 `PlantCard` 注释。
- **J-5 契约与语料变不变？** → PO：**不变**。`GET /api/plants`、`GET /api/plants/{id}` 响应结构不变，语料 schema 不变。

### UI ↔ PO
- **UI-4 视觉规范要更新哪些？** → PO：横屏详情图片占比与留白约定、头部高度约定、卡片次级字号 16px；写入 ui-style-guide。
- **UI-5 是否改版式？** → PO：不改版式（横屏仍左图右文），仅调整图片尺寸上限与头部疏密。

### QA ↔ PO
- **QA-4 封面语义怎么验？** → PO：断言「树叶分类下含花朵植物的封面为叶图、果实分类下为果图」；「全部」列表回退顺序不变。
- **QA-5 横屏图片变大的判定口径？** → PO：以**度量**为准——同视口下图片像素宽度较修复前增大、内容区留白减少；并断言图片完整不裁切、无水平溢出、页面级溢出 0。
- **QA-6 要防哪些回归？** → PO：Sprint 6 的「无滚动条 / 不退出全屏」断言、US-6/US-7 用例、TC-07 封面回退、首页卡片相关断言，全部重跑通过。

## 三、细化规则（冻结）
1. 封面选择：`category` 命中植物 `parts` 时取该部位首图；否则按 `flower→leaf→fruit` 回退；`all`（未指定分类）保持原回退顺序。
2. 横屏成图策略：`.part-img` 在横屏（`orientation: landscape`）下 `max-width` 由 40% 调整为约 48%；`.part-content` 继续 `flex: 1 1 auto` 吸收剩余宽度。
3. 头部收紧：仅在横屏范围内调整头部区块的上下留白 / 字号，不改结构、不改控件。
4. 卡片次级字号：`.plant-card-pinyin` / `.plant-card-en` 由 14px 调整为 16px。
5. 不改路由、接口契约、语料结构、缓存键；不改部位切换 / 换株 / 全屏 / 语音朗读行为。
