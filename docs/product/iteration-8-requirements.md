## 二、角色问答记录（阶段 2）
### R ↔ PO
- **R-1 卡片标题派生放哪里、如何可测？** → PO：在 `PlantCard.jsx` 内新增并导出纯函数 `deriveCardTitle(plant, category)`，内部读 `plant.id` 与 `plant.name.zh`；`.plant-card-zh` 用它渲染，便于单测直接断言。
- **R-2 花朵分类标题规则细节？** → PO：植物名**已含「花」**保持原名（桃花 / 樱花 / 菊花 / 杜鹃花…）；否则 名称+「花」（苹果→苹果花、玫瑰→玫瑰花、向日葵→向日葵花、蒲公英→蒲公英花）。
- **R-3 树叶分类标题到底叫「苹果叶」还是「苹果树叶」？** → PO：**统一「植物名 + 叶」**（见 §三细化规则 3），不逐株改用「XX 树叶」；理由见下。请在文档写明口径与理由。
- **R-4 果实分类有没有特例？** → PO：惯用果名特例表 `{ ginkgo: 白果, pine: 松果, lotus: 莲蓬 }`，其余保持植物名（苹果、香蕉、葡萄…）。依据语料中该果实本身的说法：银杏的果=白果、松树的果=松果、荷花的果=莲蓬。
- **R-5 详情默认部位规则？** → PO：入口 `category`（`location.state?.category`，缺省 `all`）为 flower/leaf/fruit 且该植物确有该部位时默认选中该部位；否则退回 `getOrderedParts(...)[0]`。换株与滑动切株后同样跟随当前分类。
- **R-6 会不会撑坏卡片布局？** → PO：卡片最小宽 220px、标题 24px，最长派生标题（如「蒲公英叶」4 字）仍在容宽内；以门禁实测无横向溢出为准，确需兜底才做最小 CSS 调整。
- **R-7 深浅链接（无 state）怎么办？** → PO：`category` 缺省 `'all'` → 退回第一个部位，行为与现状一致，不需额外处理。

## 三、细化规则（冻结）
1. `deriveCardTitle(plant, category)` 纯函数：`category === 'all'` 或未知 → 原名；`flower` → 名已含「花」原名否则 名称+「花」；`leaf` → 一律 名称+「叶」；`fruit` → 特例表命中否则原名。
2. 特例表 `{ ginkgo: '白果', pine: '松果', lotus: '莲蓬' }`，按 `plant.id` 命中。
3. **树叶分类标题口径（PO 规范，最终表述）**：树叶分类标题**统一采用「植物名 + 叶」**，**不**逐株改用「XX 树叶」。理由：语料 100 种植物中名字以「树」结尾的仅 枫树 / 松树 / 柳树 3 种，若按口语说「XX 树叶」，会让其余植物产生「蒲公英树叶」「花生树叶」「苹果树叶」这类**不自然或歧义**的说法（蒲公英、花生本身不是树）；统一为「植物名 + 叶」（苹果叶、蒲公英叶、枫树叶）既简短自然，又与「花朵/果实」两类的派生句式一致。
4. 详情默认部位：`const preferred = ['flower','leaf','fruit'].includes(category) && data.parts?.[category] ? category : null; setPart(preferred || getOrderedParts(data.parts)[0] || null);`
5. 不改路由、接口契约、语料结构；不改全屏 / 换株 / 语音朗读 / 样式行为（除非标题变长导致明显溢出，才做最小 CSS 兜底）。
