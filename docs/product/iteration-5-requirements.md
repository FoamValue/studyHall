## 一、需求基线（人工已确认的 7 项决策）
| 事项 | 冻结结论 |
|---|---|
| 朗读对象 | 只读名称本身：中文喇叭读中文名，英文喇叭读英文名；拼音、部位名、说明、典故一律不读 |
| 音源方案 | 浏览器原生语音合成（`window.speechSynthesis`），不预生成音频、不新增后端接口 |
| 位置与形态 | 中文喇叭贴中文名右侧、英文喇叭贴英文名右侧；热区 ≥56px；播放中高亮并切为「停止」图标 |
| 播放控制 | 点击播放、再点停止；中/英互斥不重叠；切换场景自动停止 |
| 适用范围 | 仅详情页（沉浸式态 + 全屏态）；首页列表卡片不放 |
| 语速 | 中/英均 `0.8×`；浏览器不支持时不渲染喇叭（优雅降级） |
| 版本 | 新增 US-7，v1.2 增量，PRD §10 |

## 二、角色问答记录（阶段 2）
### R ↔ PO
- **R-1 朗读文本具体取哪个字段？是否带部位名？** → PO：只取植物名称，`name.zh`（中文喇叭）与 `name.en`（英文喇叭）。**部位名不读**，因此切部位时朗读内容不变，但必须先停止当前朗读再展示新部位，避免残音。
- **R-2 两个喇叭的状态如何管理？** → PO：产品只约束「同一时刻最多一个在播放」，实现方式不限；建议封装为单一 hook 内部持有当前 utterance，保证互斥与统一停止。
- **R-3 深入链接 / 切植物后朗读是否自动开始？** → PO：不自动开始，必须用户点按（也符合浏览器对语音播放需用户手势的要求）。
- **R-4 英文名缺失的植物怎么办？** → PO：隐藏英文喇叭，中文喇叭照常展示；不报错、不留空位跳动。

### UI ↔ PO
- **UI-1 喇叭放哪、多大？** → PO：贴名称右侧同一行；按钮热区 ≥56px（沿用现行 UI 红线），视觉上可比热区小以保持行内协调，但点击区域不得缩水。
- **UI-2 播放中如何反馈？** → PO：按钮高亮 + 图标由「喇叭」切为「停止」，再次点按即停止；不播放时恢复喇叭图标。
- **UI-3 全屏态与平板适配？** → PO：沉浸式态与全屏态都要有喇叭，位置随名称行；不得遮挡 Sprint 4 的两侧切换按钮与全屏按钮；横竖屏均需正常。

### J ↔ PO
- **J-1 后端是否要改？** → PO：**不改**。不改接口契约、不改语料 schema、不改缓存键；朗读纯前端能力。
- **J-2 是否需要为读音提供数据？** → PO：不需要，音源来自浏览器，不引入拼音 / 音标转语音的后端逻辑。

### QA ↔ PO
- **QA-1 自动化环境无真实语音，怎么判「读出来了」？** → PO：以「点按触发了对应语言的朗读调用」为通过标准（可注入 mock / stub 断言调用与文本），不依赖真实音频与音质；真机音质由人工抽验。
- **QA-2 要覆盖哪些停止时机？** → PO：切植物、切部位、点「回花园」离开详情、组件卸载，以及任何播放中再次点按另一喇叭的互斥场景。全屏进出也应停止，避免全屏切换时残音。
- **QA-3 降级怎么验？** → PO：模拟 `window.speechSynthesis` 缺失，断言喇叭不渲染且页面其余功能（部位切换、换株、全屏）不受影响。

## 三、细化规则（冻结）
1. 中文喇叭朗读文本 = 植物中文名；英文喇叭朗读文本 = 植物英文名；两者都**不含**拼音、部位名、说明、典故。
2. 语言标记：中文 `zh-CN`，英文 `en-US`；语速统一 `0.8`。
3. 播放互斥：任一时刻至多一个 utterance 在播放；点另一个喇叭先 `cancel` 当前再 `speak`。
4. 停止时机（必须全部覆盖）：切换植物、切换部位、点「回花园」离开详情、组件卸载、全屏进入 / 退出。
5. 优雅降级：`window.speechSynthesis` 不可用时不渲染任何喇叭，页面其余功能不变。
6. 无英文名 → 隐藏英文喇叭；无中文名不可能出现（语料保证）。
7. 不改动 `GET /api/plants`、`GET /api/plants/{id}` 契约与 `content/plants/*.json` 语料。

## 五、非目标（同 PRD §10.5）
- 不预生成音频、不接第三方 / 后端 TTS。
- 不逐句朗读（拼音、部位名、说明、典故）。
- 不做语速 / 音色设置界面（固定 `0.8×`）。
- 不在首页卡片、分类列表提供朗读。
- 不做手机端专项适配。
