## 一、需求基线（人工输入 + PO 冻结决策）
| 事项 | 冻结结论 |
|---|---|
| 缺陷描述 | 进入详情页（沉浸式态 / 全屏态）后仍有纵向滚动条；滚动该区域会带动页面滚动，使 iPad Safari 退出全屏 |
| 基准设备 | **iPad 浏览器（Safari）**；横屏 1024×768 / 1180×820，竖屏 768×1024 / 820×1180 |
| 期望结果（方案 A） | 详情页**整屏呈现**：页面级与内容区**均无纵向滚动条**、内容区不可滚动；**不发生页面级滚动**，因而不退出全屏 |
| 保留项 | 图片 `object-fit: contain` 完整不裁切；文字完整可读；既有 US-6 / US-7 行为不回归 |
| 兜底 | 仅当极长文案在极端小屏确实放不下时，允许**文字卡片内部**滚动，且不得传递到页面 / 全屏 |
| 版本 | v1.3 增量，PRD §11 |

## 二、角色问答记录（阶段 2）
### R ↔ PO
- **R-1 滚动条到底出现在哪？** → PO：实测结论为「页面级溢出恒为 0，滚动条出现在内容区 `.detail-body`」（横屏 78px、竖屏 130px）。因此修复目标包含两层：消除内容区可滚动、并保证永无页面级滚动。
- **R-2 为什么 iPad Safari 滚动会退出全屏？** → PO：机制为内容区滚到边界后**滚动链式传递到页面**，页面滚动触发 Safari 退出全屏。修复须从机制上阻断（容器脱离文档流 + `overscroll-behavior`）。
- **R-3 图片高度能否不放死 `vh`？** → PO：可以。图片改为按剩余空间自适应收缩，保持完整不裁切即可；不要求固定视角高度。
- **R-4 内容放不下时怎么办？** → PO：优先「图片让位给文字」；再不行才让文字卡片内部滚动，且不得传递到页面。

### UI ↔ PO
- **UI-1 会不会改版式？** → PO：不改版式（横屏保持左图右文、竖屏保持上下），只调整溢出策略与图片尺寸策略。
- **UI-2 图片变小是否可接受？** → PO：仅在空间不足时收缩；横屏空间充足时图片不受影响。优先保证文字完整、图片完整。
- **UI-3 滚动条要不要隐藏？** → PO：不做「隐藏滚动条但可滚动」的障眼法；本迭代要求的是**内容区不可滚动**（无滚动条、也无滚动行为）；仅文字卡片兜底滚动时保持系统默认滚动条，且不传递到页面。

### J ↔ PO
- **J-1 后端是否要改？** → PO：**不改**。接口契约、语料 schema、缓存键全不变；本迭代纯前端 CSS 修复。

### QA ↔ PO
- **QA-1 头less 环境复现不了 iPad 退出全屏怎么办？** → PO：以「机制消除」为验收口径——断言 iPad 视口下页面级溢出为 0、内容区不可滚动、滚动操作不改变文档滚动位置；真机 iPad 行为由人工抽验。
- **QA-2 要覆盖哪些视口？** → PO：1024×768、1180×820（横屏）、768×1024、820×1180（竖屏），沉浸式态与全屏态都要验。
- **QA-3 怎么防回归？** → PO：既有 TC-38（沉浸式无滚动条）、TC-39（回花园记忆）、TC-40（平板适配）与 US-7 语音用例必须全部重跑通过。

## 三、细化规则（冻结）
1. 沉浸式容器脱离文档流并铺满视口（`position: fixed; inset: 0`），页面高度恒等于视口 → 永不产生页面级滚动条。
2. 容器与内容区添加 `overscroll-behavior: none / contain`，阻断滚动链式传递（页面 / 全屏不受任何滚动影响）。
3. 内容区 `.detail-body` 不可滚动（`overflow: hidden`）。
4. 图片不再写死视角高度：按剩余空间自适应收缩，保持 `aspect-ratio: 1/1` 与 `object-fit: contain`。
5. 文字卡片为兜底滚动容器，仅在极长文案 + 极端小屏时内部滚动，且 `overscroll-behavior: contain`。
6. 不改路由、不改后端契约与语料、不改部位切换 / 换株 / 全屏 / 语音朗读行为。

## 五、非目标（同 PRD §11.5）
- 不重做详情页视觉版式，仅调整尺寸与溢出策略。
- 不新增滚动容器、不做内容分页 / 折叠。
- 不做手机端专项适配。
